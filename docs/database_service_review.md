# 数据库与后端服务审查及验证记录

审查日期：2026-10-18。范围为四份核心技术文档、根目录玩法规则、后端源码、前端调用点和容器配置。初次按用户要求只做静态审查；用户随后明确要求补写测试并进行上线前验证，已完成双端构建、291 项自动化测试及 6 项生产产物冒烟检查，详见第 6 节。实际玩家数据库未打开或迁移，测试仅使用内存库和自动清理的系统临时数据库。

## 1. 结论与系统划分

SQLite 适合当前单进程、小规模熟人局；人员、余额流水与全局配置落库，在线状态和快捷消息留在内存也合理。但当前设计**尚不能保证一整局资金的可恢复性**，不宜因为单笔余额事务正确就认定经济系统已经完善。

| 系统 | 当前实际能力 | 判断 |
| :--- | :--- | :--- |
| 人员与身份 | 管理员开通普通玩家，密码哈希、昵称头像、角色、登录凭据版本 | 基础链路存在；封禁、角色编辑、账号停用/删除未实现 |
| 经济与账本 | 可用筹码余额、初始赠送、管理员充减、底注/下注/奖金流水 | 单笔原子写入；没有线上收付款、重复请求去重或完整对账机制 |
| 房间与在线状态 | 内存房间、8 座、观战、准备、断线重连、多连接 | 单进程可用；没有房主实体、持久化房间或离线座位过期策略 |
| 牌局与裁判结算 | 双牌库发牌、轮转、比牌、多人裁决、派奖 | 属于独立业务系统；缺少持久化牌局编号、在途底池与中断处理 |
| 规则配置与模拟 | 配置校验、全局配置落库、下一局生效、真实采样 | 主链路存在；没有配置修订与经办人历史 |
| 管理审计 | 资金流水、真实经办人和房间关联 | 尚非完整操作审计，改密等操作未留专门事件记录 |
| 实时消息与运维恢复 | 鉴权消息、聊天、容器与数据库目录挂载 | 已补明显错误；备份、恢复演练和在途资金恢复仍未形成完整方案 |

## 3. 确定存在、尚未修复的缺口

### 3.1 高优先级：中断局丢失在途资金

[Room.startGame / bet / compare](../server/src/game/Room.ts) 已把玩家投入扣入持久化流水，但 `totalPot`、参与者和手牌仅在内存；[RoomManager.rooms](../server/src/game/RoomManager.ts) 在进程重启后为空。派奖前退出会造成玩家余额已经减少、底池却无法恢复。结算写库失败时也缺少持久化重试与补偿状态。数据库持久化目录、WAL 和单笔事务均不解决此问题。

后续应首先确定“恢复中断牌局”或“退还中断局投入”的政策，再增加唯一牌局编号、投入归属、持久化结算状态及重复执行保护。本轮没有擅自规定退款政策或实现未经运行验证的整局恢复系统。

### 3.2 重复调账没有业务请求去重

管理员充值/扣减重复发出，会形成两笔真实入账；账本事务只保证每一次调用自身一致。若需要网络重试或防止重复点击，需在接口和数据库共同引入唯一业务请求编号，重复执行返回原结果。当前不应自动重试资金变更请求。

### 3.3 金额最小单位未定义

闷牌半注和循环克制平分会产生小数，三人平分还可能不能用有限小数表示。当前 JavaScript 数值及 SQLite 数值存储不是精确货币账本；本轮有限值/范围校验没有消除所有浮点误差。最小筹码单位、余数归属和公平轮换规则待确定，不能直接把字段改为整数而改变玩法。

### 3.4 管理页面与后台真实能力不一致

[AdminDashboard](../client/src/views/AdminDashboard.tsx) 用户列表和部分资金记录来自浏览器本地数据，若干写操作捕获接口失败后仍本地更新并显示成功；[LedgerDrawer](../client/src/views/LedgerDrawer.tsx) 使用模拟流水。删除、封禁、角色编辑及充值专账接口未实现，不能将界面成功当作数据库已更新。此次修正核心文档的能力标识，完整页面接入及错误处理留待后续。

### 3.5 完整审计与运维能力仍欠缺

改密、配置保存及其他非资金管理操作没有专门审计记录；没有登录失败审计或登录限流。当前也没有服务端会话列表和逐会话主动退出撤销。单个游戏服务实例是当前房间内存架构的边界，不能仅靠共享数据库运行多个实例。

## 4. 尚需确定的产品规则

- **开局权限**：现在是至少两人在座且全员准备后自动开局，没有房主字段或房主开局事件。只有房主能开局需要另行定义房主产生、离开转移、重连及强制开始条件。
- **全押**：当前仅扣光余额并继续保留 `active`，没有独立全押状态或边池；后续轮到零余额玩家仍无法继续跟注。若要采用通常的全押参与终局规则，须明确可争夺奖池上限和不同投入层级的分配。
- **提现**：当前仅管理员记线下扣减。真实线上提现需要申请、审核、冻结、付款、失败退款等链路，不能与本地扣筹码等同。
- **账号与房间生命周期**：停用与删除的差别、历史账本保留、私密房间准入、断线无限期占座及无限时房间的处置策略尚未确定。
