## 后续发布与维护

`install-release.sh`（仅本机保留） 安装运行环境、生产依赖、专用用户与服务，不会自动停止正在运行的游戏服务。后续更新必须先结束所有牌局、生成数据库一致备份，再进入维护期停止服务；安装新版本后通过 `current` 切换发布目录。旧代码目录可以保留作为回退版本，回退前须确认数据库结构兼容，不可直接覆盖当前数据库。

常用服务器检查：

```bash
systemctl status zjh-game.service nginx.service --no-pager
journalctl -u zjh-game.service -n 80 --no-pager
systemctl list-timers certbot.timer --no-pager
/opt/zjh-game/runtime/bin/node --version
```

本机重复公网检查需先安装本机测试目录中的专用依赖，使用私有交付文件运行：

```bash
node deploy/native/verify-live.mjs /absolute/path/to/deployment-access.local
```

该检查仅创建临时观战房间并测试同一账号的两个连接，断开后清理；不开户、不入座、不下注，不将模拟页面当作真实对局验收。目前为同机更新前备份及初始备份的临时恢复验证，未配置周期性异地备份。

## 已知业务边界

正式页面已移除默认模拟管理员、登录失败模拟回退、默认房间、机器人自动下注、调试浮条和固定测试账本。独立模拟仓库仅供回归测试，正式 App 不导入。账号由管理员创建，普通玩家登录进入大厅；创建时选择 2～8 人，加入后点击“入座参与”，全员点击“准备”。每局结束后重新准备。限时房间仍有服务端超时弃牌；无限制房间不自动行动。

管理员页面真实读取账号及全站流水，开号、调筹码、改密仅在服务端成功后提示成功；未实现的封禁、删除、角色变更操作没有保留假按钮。旧模拟身份缓存会被清理，保存的真实令牌也须经服务端验证后恢复身份。

账户、余额和流水可持久化；房间、牌局及未结算底池不能跨进程重启恢复。更新或回滚必须在所有牌局结束后进行，数据库备份不能替代中断牌局恢复。旧代理继续保持停用，证书续期不得调用恢复旧代理的钩子。
